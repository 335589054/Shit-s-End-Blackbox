## 1. 设计约束

| 约束 | 影响 |
|---|---|
| 运行时无 Root | 所有特权操作必须经 Shizuku（shell, uid 2000） |
| 无 Gradle / 无 AndroidX | 纯框架 API + 手写构建脚本；避免依赖传递与守护进程内存开销 |
| 低内存构建机 | 单次 `kotlinc` + `d8` 编译，不使用 Gradle daemon |
| Android 8–16 | 反射适配多版本 `IPackageManager` 签名；appops 名称做兼容表 |
| 可回滚 | 删除前强制备份并校验；失败自动回滚 |
| 隐私 | 应用自身不采集/不联网；日志脱敏 |

## 2. 构建方案（无 Gradle）

### 2.1 目录结构

```
shitsendblackbox/
├─ build.py                     # 一键构建
├─ docs/                        # 文档
├─ app/
│  ├─ AndroidManifest.xml
│  ├─ res/                      # 仅图标、strings、themes
│  ├─ assets/
│  │  ├─ blocklist.json         # 种子黑名单
│  │  └─ stub.p12               # 顶替包签名密钥（构建期生成）
│  └─ src/mai/solium/shitsendblackbox/
│     ├─ App.kt
│     ├─ ui/…                   # 4 个页面 + 控件
│     ├─ core/…                 # Shizuku、Shell、日志、JSON、包信息
│     ├─ cleaner/…              # 扫描、备份、删除、Stub 生成、恢复
│     ├─ permission/…           # 区域、策略引擎、appops
│     ├─ network/…              # VPN、DNS、IP 规则
│     └─ data/…                 # 存储与种子数据
├─ keystore.jks                 # 应用签名（构建期生成，不入库）
└─ README.md
```

### 2.2 工具链

| 工具 | 版本 | 用途 |
|---|---|---|
| JDK | 17+（本机 21） | kotlinc / d8 / apksigner 运行环境 |
| Kotlin compiler | 2.1.0（CLI 发行版） | 编译 `.kt` |
| Android SDK Platform | android-36 | `android.jar` 编译 classpath |
| build-tools | 36.0.0 | `aapt2`、`d8`、`zipalign`、`apksigner` |
| Python | 3.12 | 编排构建、打包 zip、校验 |

依赖 jar（手动放入 `out/libs/`，构建脚本自动下载/复用）：

- `shizuku-api-13.1.5.jar`、`shizuku-provider-13.1.5.jar`、`shizuku-aidl-13.1.5.jar`
- `apksig-8.7.3.jar`（自包含，用于运行期签名 Stub）
- `kotlin-stdlib-2.1.0.jar`

### 2.3 构建步骤

```
python build.py
```

1. **准备**：校验 SDK、`android.jar`、build-tools；缺 Kotlin/apksig 时下载到 `out/tools`。
2. **编译 Kotlin**：
   ```
   kotlinc -jvm-target 1.8 -no-reflect \
     -classpath android.jar:shizuku-api.jar:shizuku-provider.jar:apksig.jar \
     -d out/classes $(find app/src -name '*.kt')
   ```
3. **资源**：
   ```
   aapt2 compile --dir app/res -o out/res.zip
   aapt2 link -o out/base.apk -I android.jar \
     --manifest app/AndroidManifest.xml -R out/res.zip \
     --min-sdk-version 26 --target-sdk-version 36 \
     --version-code 1 --version-name 0.1 \
     --java out/gen
   ```
   - 代码中**不引用 `R.*`**（界面全部用代码构建，字符串常量集中在 `Strings.kt`），避免 javac 编译 R 类。
4. **Dex**：
   ```
   d8 --min-api 26 --release --output out/dex \
     out/classes/**/*.class kotlin-stdlib.jar apksig.jar
   ```
5. **打包**：Python `zipfile` 将 `classes.dex`、`assets/*` 写入 `out/base.apk`。
6. **对齐/签名**：
   ```
   zipalign -f 4 out/base.apk out/aligned.apk
   apksigner sign --ks keystore.jks --ks-pass pass:… --out out/app-release.apk out/aligned.apk
   ```
7. **验证**：`apksigner verify --print-certs`、`aapt2 dump badging`，输出 SHA-256。

首次运行自动生成：

- `keystore.jks`（应用签名，RSA 2048，有效期 30 年）
- `app/assets/stub.p12`（Stub 专用签名，**与应用签名不同**，PKCS12）

### 2.4 为什么不用 Gradle

- 构建机可用内存仅约 2.7 GB，Gradle + Kotlin daemon 容易 OOM；
- 项目无 AndroidX、无注解处理器、无多 flavor，手工步骤可控；
- 构建时间稳定在 30–60 秒，便于快速迭代。

## 3. 运行时架构

### 3.1 分层

```
┌──────────────────────────── UI 层 ────────────────────────────┐
│ MainActivity（4 页：清理 / 权限 / 网络 / 设置）               │
│  CleanerPage  PermissionPage  NetworkPage  SettingsPage       │
└──────────────┬───────────────────────────────────────────────┘
               │ 仅调用服务层接口，不直接拼 shell
┌──────────────▼──────────── 领域层 ────────────────────────────┐
│ Scanner  Cleaner  StubBuilder  BackupStore  PolicyEngine      │
│ ZoneStore  BlocklistStore  IpRules  DnsPolicy                 │
└──────────────┬───────────────────────────────────────────────┘
               │
┌──────────────▼──────────── 系统访问层 ────────────────────────┐
│ ShizukuManager（权限）  Shell（sh -c，超时/流式）             │
│ PackageManager 查询  AppOps  NetPolicy  ActivityManager       │
└──────────────┬───────────────────────────────────────────────┘
               │ Binder / app_process
┌──────────────▼──────────── 系统服务 ──────────────────────────┐
│ PackageManagerService  AppOpsService  NetworkPolicyManager    │
│ ActivityManagerService  VpnService（本进程）                  │
└───────────────────────────────────────────────────────────────┘
```

### 3.2 组件清单

| 组件 | 类型 | 说明 |
|---|---|---|
| `MainActivity` | Activity | 单 Activity + 4 个 Fragment；底部/顶部标签切换 |
| `ShizukuProvider` | ContentProvider | Shizuku 授权回调，`authorities=${applicationId}.shizuku`，`exported=true` |
| `BlockVpnService` | VpnService | 前台服务，DNS 代理 + IP 丢包 |
| `GuardJobService` | JobService | 周期复查（15 分钟，仅充电/空闲约束可放宽） |
| `BootReceiver` | Receiver | `BOOT_COMPLETED`、`MY_PACKAGE_REPLACED` 后重放策略 |
| `PackageChangeReceiver` | Receiver | `PACKAGE_ADDED/REPLACED/REMOVED`，检测被顶替包是否被系统还原 |
| `PackageUninstaller` | 普通类（app_process 入口） | `main(String[])`，运行于 shell uid |

### 3.3 线程模型

- UI 线程只做渲染；
- `App.executor`：固定 4 线程池，执行扫描、命令、备份；
- 所有 shell 调用同步阻塞在后台线程，默认超时 15 s（删除/安装 120 s）；
- 结果通过 `Handler(Looper.getMainLooper())` 回投；
- VPN 读包线程独立（`Thread`，daemon），DNS 处理用小线程池（2–4 线程）。

### 3.4 关键流程

#### 扫描

```
UI → Scanner.scan()
  ├─ PackageManager.getInstalledPackages(GET_PERMISSIONS|GET_SIGNATURES|MATCH_UNINSTALLED?)
  ├─ 过滤：system / 3rd-party
  ├─ 读取 ApplicationInfo.flags、permissions、targetSdk、installer
  ├─ 读取签名摘要（SHA-256）
  ├─ 风险评分（规则见 04）
  └─ 返回 List<AppInfo>，按分数降序
```

#### 卸载并顶替

```
UI → Cleaner.replace(pkg)
  1. BackupStore.backup(pkg)         // pm path → cat 流 → 校验 SHA-256
  2. Shell.deletePackage(pkg)        // app_process + 反射 deletePackageAsUser
  3. 轮询 pm list packages 直到消失（≤10 s）
  4. StubBuilder.build(pkg)          // AXML + zip + apksig 签名
  5. Shell.installStream(stubBytes)  // pm install -S <size>
  6. 校验 dumpsys 版本号/签名
  7. 失败 → BackupStore.restore(pkg) → 上报错误
```

#### 恢复

```
UI → Cleaner.restore(pkg)
  1. 若存在 Stub：Shell.uninstall(pkg)（pm uninstall → 失败则 deletePackageAsUser）
  2. BackupStore.load(pkg) → base + splits
  3. Shell.installMultiple(paths)（流式 pm install-create/write/commit）
  4. 校验签名/版本；恢复 enabled 状态与 appops
```

#### 策略应用（区域）

```
PolicyEngine.apply(zone)
  for each app in zone:
    黑: force-stop; appops LOCATION=ignore; PROJECT_MEDIA=deny;
        RUN_ANY_IN_BACKGROUND=ignore; netpolicy restrict; 可选 pm disable-user
    灰: appops LOCATION=foreground; PROJECT_MEDIA=foreground?（见 03）;
        netpolicy restrict-background; 不 force-stop
    白: appops LOCATION=allow; PROJECT_MEDIA=allow; netpolicy allow;
        反卫星直读时 FINE=ignore / COARSE=allow
  汇总每条命令的 exit code，返回失败清单
```

#### VPN

```
BlockVpnService.onStartCommand
  ├─ Builder: addr 10.111.0.2/32, dns 10.111.0.1, route 10.111.0.1/32
  ├─ 对每条 blocked CIDR addRoute()
  ├─ establish() → ParcelFileDescriptor
  ├─ reader 线程：read → IPv4/UDP:53 → DnsProxy；命中 blocked IP → drop
  └─ 前台通知（拦截计数、停止按钮）
```

## 4. 数据持久化

| 文件 | 位置 | 内容 |
|---|---|---|
| `zones.json` | `filesDir` | 包名 → 区域、更新时间、备注 |
| `blocklist_user.json` | `filesDir` | 用户新增域名/IP、启停状态 |
| `settings.json` | `filesDir` | 总开关、上游 DNS、反卫星、主题 |
| `backups/<pkg>/meta.json` | `filesDir/backups` | 版本、签名、split 列表、校验和 |
| `backups/<pkg>/*.apk` | 同上 | 原始安装包 |
| `logs/app.log` | `filesDir/logs` | 环形日志（≤ 1 MB，滚动 3 份） |

不使用数据库：数据量小、需要可读可导出、避免引入 Room。

## 5. 错误处理

- **命令层**：`Shell.Result(exitCode, stdout, stderr, timedOut)`；非 0 一律抛出 `ShellException`，消息保留 stderr 末 2 KB。
- **业务层**：每步失败都带 `step` 标记（backup/delete/install/verify），便于回滚定位。
- **UI 层**：`Toast` + 详情对话框（可复制错误）；批量任务显示进度与逐项结果。
- **超时**：删除 60 s、安装 120 s、普通命令 15 s；超时后 `destroy()` 进程。
- **幂等**：重复点击按钮通过 `AtomicBoolean` 锁；任务队列串行化删除/安装。

---

## 6. 安全设计

- 导出的组件最小化：仅 `ShizukuProvider`（Shizuku 要求）与 `BootReceiver`（`exported=false` 亦可收到系统广播）。
- `BlockVpnService` 不导出；通过 `startForegroundService` 启动。
- 备份目录 `filesDir` 私有；导出走 SAF，由用户显式选择。
- Stub 签名密钥随 APK 分发，仅用于“制造不同签名”，不承担身份认证职责。
- 日志脱敏：IMEI/IMSI/手机号正则替换为 `***`。
- 不申请 `QUERY_ALL_PACKAGES` 以外的敏感权限；`QUERY_ALL_PACKAGES` 需在 manifest 声明并在设置中说明用途。

## 7. 兼容性策略

| 差异点 | 处理 |
|---|---|
| `deletePackageAsUser` 参数个数/类型随版本变化 | 反射遍历方法名 + 参数匹配，支持 4/5 参数；失败回退 `pm uninstall --user 0` |
| appops 操作名差异 | `AppOpsNames` 兼容表（`PROJECT_MEDIA`/`RECORD_AUDIO`/`FINE_LOCATION`…） |
| `pm install` 流式参数 | 优先 `pm install -S`；失败回退写 `/data/local/tmp`（shell 可写）后安装 |
| 分区只读 | 仅操作 `/data` 侧（禁用/卸载用户），不改 system 分区 |
| 厂商拦截 | 所有命令失败均返回原始 stderr，界面展示“厂商可能拦截” |

## 8. 测试策略

- **单元级**：纯 Kotlin 逻辑（AXML 生成、DNS 报文、CIDR 匹配、风险评分）用 `kotlinc` 编译后以 JVM `main` 自测，不依赖设备。
- **设备级**：`adb` 脚本驱动（安装、注入测试包、点击、断言 `dumpsys`/`pm list`/DNS 查询）。
- **回归清单**：见 `03` 的验证矩阵，每次发布前重跑。

## 9. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 删除后无法安装 Stub（签名残留） | 先小范围验证；失败自动恢复；文档标注 |
| 删除关键包导致无法开机 | 关键包黑名单 + 输入包名确认 + 默认禁止 |
| OTA 因 Stub 失败 | 提供“恢复全部”入口；说明副作用 |
| VPN 与其它 VPN 冲突 | 检测已有 VPN，提示先关闭；失败给明确错误 |
| 厂商 ROM 限制 appops | 逐条上报失败，不假装成功 |
