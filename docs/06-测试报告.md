## 3. 测试中发现并修复的问题

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| B1 | 普通应用“卸载并顶替”删不掉 | 对普通应用传了 `DELETE_SYSTEM_APP`（5），PMS 静默失败 | `Cleaner` 按 `app.system` 选择 `flags=5` 或 `0` |
| B2 | `pm install` 报 `Failed to parse APK file: /storage/emulated/0/...` | shell 进程无权读应用外部私有目录 | 先 `cp` 到 `/data/local/tmp/blackbox` 并 `chmod 644` 再安装 |
| B3 | `内置黑名单读取失败: blocklist.json` | `build.py` 把 assets 写到了 APK 根目录 | 写入 `assets/<relpath>` |
| B4 | Shizuku 始终 `NOT_RUNNING` | `aapt2` 不替换 `${applicationId}`，provider authority 与包名不匹配 | manifest 改为字面量 `mai.solium.shitsendblackbox.shizuku` |
| B5 | VPN 建立后读循环立即退出（`lastN=0`） | 该内核/模拟器上 `read()` 在无数据时返回 0 | 把 0 视为“暂无数据”，`sleep(5ms)` 后重试；`<0` 才退出 |
| B6 | 删除偶发超过 8 s 未完成 | 系统应用删除慢 | `waitGone` 超时 8 s → 20 s |
| B7 | 系统包顶替失败后原包未恢复 | 无回滚分支 | v1 失败时 `restoreApk`；**v2 按用户要求改为“保持删除”**，备份保留可手动恢复 |
| B8 | 权限页切换分区误点到其他应用 | 列表按分区变化重排，点击坐标偏移 | 保持 `render()` 只重建网格与列表容器；后续可加二次确认 |
| B9 | 访问 `1.1.1.1` 等公共 DNS 的普通 TCP 也被丢包 | `BlockVpn` 为“常见 DNS 服务器”额外添加了 /32 路由，非 53 端口流量被拉进 tun 丢弃 | 删除该路由列表，只保留 `10.111.222.0/24` 与黑名单 IP 路由；DNS 仍由 `addDnsServer` 接管 |

## 4. 未覆盖 / 待复验

1. **异签名顶替在 MIUI / OS4 / Android 17 上的行为**：v2 在 Xiaomi 17（OS4.0 / Android 17，
   SDK 37）实测：`deletePackageAsUser` 返回 `DELETE_REQUESTED`、`pm path` 变空，但 PMS 仍保留
   原签名记录，占位包安装返回
   `INSTALL_FAILED_UPDATE_INCOMPATIBLE: Existing package ... signatures do not match newer version;
   ignoring!`。因此 OS4 上“异签名顶替”仍不可用，程序按策略保持删除（可随时恢复）。
2. **DoH/DoT 与硬编码 IP**：当前覆盖明文 DNS 与已知 IP；应用内“测试 IP”已验证丢包，
   DoH/DoT 绕过仍需后续加应用级断网或 IP 规则。
4. **重启后策略持久化**：分区/黑名单已持久化，但 Shizuku 服务需用户重新启动；
   可考虑加入启动引导页。
5. **Shizuku shell 模式**（非 root）：本次以 root 启动服务，真机需验证无线调试启动路径。
6. **长时间稳定性**：VPN 前台服务、通知、系统杀后台等场景未做 24 h 压测。

已知限制（无 Root）：
- 黑区网络限制作用于**后台**；应用在前台时无法被系统级断网，v3 用 `pm suspend` 冻结等价处理。

- 部分厂商 ROM（HyperOS/ColorOS）对 `pm suspend` 有白名单，失败会在页面回退并提示。
